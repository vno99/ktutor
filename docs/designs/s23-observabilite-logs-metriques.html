Infrastructure

s23 — Observabilité : logs, traces, métriques

Pas d'écran utilisateur. Design technique de référence pour le backend.

Composants du système (non-UI)

  • Middleware HTTP — log chaque requête avec request_id, route, duration_ms, pseudo (extrait du JWT).
  • Loguru (JSON) — format structuré : timestamp, level, message, extra (request_id, pseudo, route, duration_ms).
  • OpenTelemetry — traces exportées console (local) ou OTLP (si OTEL_EXPORTER=otlp).
  • LLM wrapper — log chaque appel avec duration_ms, model, prompt_tokens, completion_tokens (quand disponibles).
  • Celery tasks — log au démarrage, succès et échec (si tâches présentes dans le projet).
  • Prometheus /metrics — endpoint sans auth (local) exposant au minimum 5 compteurs.

Fichiers impactés (référence technique)

  • backend/app/core/logging.py
  • backend/app/core/config.py
  • backend/app/main.py (middleware + lifespan OTEL)
  • backend/app/core/observability/ (nouveau)
  • backend/app/api/metrics.py (nouveau endpoint)
  • backend/app/services/llm/client.py (wrapper log)
  • requirements.txt (ajout packages)
  • .env (variables OTEL / METRICS)

Référence uniquement — pas de code copiable. L'implémentation se fait dans le backend via le pipeline standard. Aucun composant UI du design system (Button, Card, Header, etc.) n'est impliqué dans cette story.
