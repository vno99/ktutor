## Findings

**#1 — minor — `app/api/evaluations/router.py`** — The plan ("Run interdicts" section) says the router should use loguru structured JSON with fields `pseudo`, `route`, `duration_ms`, `status`, `score_present` (bool). The implementer logs only on refusals (`kind`, `pseudo`, `message`) and on tempfile-cleanup failure. **No successful-upload log** is emitted. The same gap exists in the documents router (s10) — precedent, not s18-specific. The plan's negative requirement (never log `teacher_comments`, `annotations`, score value, OCR text) is respected. Observability gap; not s18-blocking.

**#2 — minor — `backend/app/services/ocr/evaluation_extractor.py`** — The `SCORE_RE` anchoring (`\b(\d+)\s*/\s*(\d+)\b`) is not covered by a dedicated false-positive test. The current suite uses only well-formed `12/20` patterns that match with or without the `\b` boundaries, so a regression that drops the anchoring is invisible. Research Piège 4 explicitly flagged "élève noté 12 sur 20" as a false-positive risk; the LLM JSON is the documented safety net for ambiguous scores (per the research). Not s18-blocking; could be hardened in a follow-up test.

**#3 — minor — `backend/app/services/rag/ingestion.py`** — The plan's "Files touched → Modified" list does NOT include `ingestion.py`, but the file is modified (+7/-2) to add the optional `raw: dict | None = None` field to the forward-declared `OcrResult`. This is a logical consequence of the `OcrResult` contract change (the forward declaration exists to keep the type shape consistent). The plan's `Not modified` list at line 417-420 does NOT include `ingestion.py` either, so the plan is silent on this file. The implementer made the minimum-necessary change.

**#4 — minor — `tests/api/test_evaluations.py:502`** — `test_upload_uses_jwt_pseudo_not_form` docstring claims "No row for bob is created in the DB" but the assertions only check `response.status_code == 422` and `eval_service_stub.calls == []`. The DB session is not opened to confirm zero `Evaluation(student_pseudo="bob")` rows. The contract is asserted via the service-stub-call-list, not via the DB. Strong enough because the FK constraint would catch a non-existent pseudo anyway; mutation 3 above proves a regression that removes the field rejection is caught.

**#5 — minor — `backend/app/api/evaluations/router.py:53-58`** — The plan called for the AC1 override to be documented in the research and recap'd in the router's docstring. The router docstring does mention the override (lines 53-58) and the research Drift 1 is documented. `docs/stories.md` is NOT edited (verified empty diff) — consistent with the plan's Tâche 9.
