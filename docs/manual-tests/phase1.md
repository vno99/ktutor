# Phase 1 POC — End-to-End Test Guide

> Stories covered: **s01-uploader-document**, **s02-chatter-avec-mon-cours**,
> **s03-generer-qcm**, **s04-repondre-qcm**.
> Audience: a human with a workstation, Docker, Python 3.12+, and a
> free OpenRouter API key (or any OpenAI-compatible LLM provider).

This guide verifies the **end-to-end runtime behavior** of the Phase 1
POC. The 189 unit tests in `backend/tests/` lock the in-process logic;
this guide exercises the _running_ services (Postgres, SeaweedFS,
ChromaDB) and the _real_ LLM call.

If you only want the unit-test view, run:

```bash
cd backend
pytest --cov=app --cov-fail-under=80 -m "not integration"
# 189 passed, coverage 86.54%
```

## 1. Prerequisites

### 1.1. Services Docker

```bash
cd C:/Workspace/ktutor
docker compose up -d seaweedfs postgres redis chroma
docker compose ps
```

You should see 4 services, all `healthy`:

| Service | Host port | Container port |
| --- | --- | --- |
| `ktutor-seaweedfs` | 8333 | 8333 |
| `ktutor-postgres` | 5432 | 5432 |
| `ktutor-redis` | 6379 | 6379 |
| `ktutor-chroma` | 8500 | 8000 |

**Port conflicts.** The `docker-compose.yml` binds `chroma`'s container
port 8000 to host 8500 (so 8000 is free on the host even if another
process is listening there). If you have another process on 5432, 6379,
or 8333, stop it first or change the host port in `docker-compose.yml`.

### 1.2. Python dependencies

```bash
cd backend
pip install -r requirements.txt
```

The key packages: `sqlalchemy>=2.0`, `psycopg[binary]>=3.1`, `chromadb>=0.5`,
`fastembed>=0.3`, `minio>=7.2`, `langchain-openai>=0.2`,
`langchain-text-splitters>=0.3`, `langchain-community>=0.3`.

### 1.3. Configuration

Copy the project `.env` to `backend/.env` and append the Phase 1
block. pydantic-settings reads `.env` from the **current working
directory**, so `backend/.env` is required even if a `.env` exists at
the repo root.

```bash
cp /path/to/repo/.env backend/.env
cat >> backend/.env <<'EOF'

# === Phase 1 POC ===
DATABASE_URL=postgresql+psycopg://ktutor:ktutor@localhost:5432/ktutor
S3_ENDPOINT=localhost:8333
S3_ACCESS_KEY=ktutor
S3_SECRET_KEY=ktutor-secret
S3_BUCKET=assistant-documents
LLM_PROVIDER=minimax
LLM_API_KEY=sk-or-v1-<your_openrouter_key>
LLM_MODEL=minimax/minimax-m3:free
LLM_BASE_URL=https://openrouter.ai/api/v1
EOF
```

**`DATABASE_URL` must use `postgresql+psycopg://`** (psycopg 3 explicit
dialect), not `postgresql://` (which falls back to psycopg 2, not
installed).

**OpenRouter** is the cheapest path to a real LLM (free tier,
no credit card). Get a key at https://openrouter.ai. Alternatively
swap to OpenAI by setting `LLM_PROVIDER=openai`, `LLM_API_KEY=sk-...`,
`LLM_MODEL=gpt-4o-mini`, `LLM_BASE_URL=https://api.openai.com/v1`.

Without a working `LLM_API_KEY`, the `chat` and `generate-qcm` commands
will fail at runtime. The `upload` and `submit-qcm` commands do **not**
require an LLM and will work end-to-end with the seeded `Exercise`
below.

## 2. The four stories end-to-end

Each section walks one story from input to observable output. Every
command exits with a documented code; a non-zero code is the
failure signal.

### 2.1. s01 — Upload a document

**Input**: `tests/fixtures/sample_cours.pdf` (a small PDF about
dérivées, generated by `conftest.make_sample_pdf`).

```bash
cd backend
python -m app.cli upload ../tests/fixtures/sample_cours.pdf --pseudo ali --subject maths --json
```

**Expected output**:

```json
{
  "status": "indexed",
  "document_id": "<uuid>",
  "chunks_count": 1,
  "duration_ms": 700,
  "collection": "rag_maths_ali",
  "s3_key": "students/ali/<uuid>",
  "ocr_confidence": null
}
```

**Note the entries**:

- `collection: rag_maths_ali` — ChromaDB collection is named
  `rag_<subject>_<pseudo>` (ADR 004).
- `s3_key: students/ali/<uuid>` — SeaweedFS key has the
  `students/<pseudo>/<document_id>` prefix (multi-tenant invariant).

### 2.2. s02 — Chat against the document

```bash
python -m app.cli chat --pseudo ali --subject maths \
  --question "Qu'est-ce qu'une dérivée ?" --json
```

**Expected output** (truncated, accents in real output):

```json
{
  "answer": "D'après les extraits de ton cours, la dérivée...",
  "sources": [
    {"filename": "sample_cours.pdf", "chunk_index": 0}
  ]
}
```

**Verifications**:

- The answer mentions `f'(a) = lim (f(a+h) - f(a)) / h quand h -> 0`
  and the example `f(x) = x^2 → f'(x) = 2x` — both come from the
  uploaded PDF. **No hallucination**: the prompt locks the agent
  to the retrieved chunks.
- At least one source citation is present.
- The `chunk_index` is an integer (Pydantic 2 coerces the
  string-formatted index the LLM sometimes returns).

If the LLM provider is unreachable or returns malformed JSON, you get
a `QcmGenerationError("malformed_output")` analogue (s02 uses a
fallback: the agent returns "Je n'ai pas trouvé d'information…"
without crashing). This is **not** a CI failure — it's the
deterministic fallback when the collection is empty.

### 2.3. s03 — Generate a QCM

```bash
python -m app.cli generate-qcm --pseudo ali --subject maths \
  --document-id <document_id_from_2.1> --n 3 --json
```

**Expected output**:

```json
{
  "exercise_id": "<uuid>",
  "questions": [
    {
      "question": "Comment est définie la dérivée d'une fonction f en un point a ?",
      "options": ["...", "...", "...", "..."],
      "correct_index": 0
    },
    { "...": 2 more questions, each with 4 options and correct_index in [0, 3] }
  ]
}
```

**Verifications**:

- 3 questions, each with **exactly 4 options** and a `correct_index`
  in `[0, 3]` (Pydantic enforces `Field(ge=0, le=3)` and
  `Field(min_length=4, max_length=4)`).
- The questions are anchored on the document content
  (dérivées, x², variable h, etc.).
- `exercise_id` is a fresh UUID you can pass to `submit-qcm`.

### 2.4. s04 — Submit answers

**Perfect score** (re-using the 3-question QCM above):

```bash
python -m app.cli submit-qcm --pseudo ali \
  --exercise-id <exercise_id_from_2.3> --answers '[0,1,2]' --json
```

```json
{
  "is_success": true,
  "correct_count": 3,
  "total": 3,
  "feedback": "Toutes les réponses sont correctes.",
  "attempt_id": "<uuid>",
  "attempt_number": 1
}
```

**One wrong** (Q1 wrong, Q2-Q3 right):

```bash
python -m app.cli submit-qcm --pseudo ali \
  --exercise-id <exercise_id_from_2.3> --answers '[1,1,2]' --json
```

```json
{
  "is_success": false,
  "correct_count": 2,
  "total": 3,
  "feedback": "2/3 réponses correctes.",
  "attempt_id": "<uuid>",
  "attempt_number": 2
}
```

**Verifications**:

- `attempt_number` increments per `(pseudo, exercise_id)` —
  submitting again returns `3`, then `4`, etc.
- `is_success` is **true iff all answers match** (AC2: it's
  all-or-nothing, not a partial credit).
- The attempt is persisted in PostgreSQL (table `attempts`).
  You can verify with:

  ```bash
  docker exec ktutor-postgres psql -U ktutor -d ktutor -c \
    "SELECT student_pseudo, exercise_id, attempt_number, is_success FROM attempts;"
  ```

## 3. Multi-tenant invariants (the load-bearing tests)

These are the three tests that fail if a future change breaks the
isolation guarantees. Run them after every code change that touches
`Retriever`, `QcmGenerator`, or `QcmGrader`.

### 3.1. Isolation par collection ChromaDB

```bash
# Upload for ali
python -m app.cli upload ../tests/fixtures/sample_cours.pdf --pseudo ali --subject maths
# Upload for bob (same subject, same file — distinct collection)
python -m app.cli upload ../tests/fixtures/sample_cours.pdf --pseudo bob --subject maths
```

Open http://localhost:8333 in a browser (or use
`mc --json alias set local http://localhost:8333 ktutor ktutor-secret`)
and verify the bucket `assistant-documents` contains two distinct
prefixes:

```
students/ali/<doc_id_ali>/
students/bob/<doc_id_bob>/
```

In ChromaDB, list the collections via the API:

```bash
curl -s http://localhost:8500/api/v1/collections | python -m json.tool
```

You should see `rag_maths_ali` and `rag_maths_bob` as two separate
collections, with no overlap.

### 3.2. Chat cross-tenant (bob asks about ali's data)

```bash
# Bob has uploaded nothing
python -m app.cli chat --pseudo bob --subject maths \
  --question "Qu'est-ce qu'une dérivée ?" --json
```

**Expected**: the "no document" fallback message, **not** ali's
content. The retriever fails to find anything in `rag_maths_bob` and
the agent returns the no-document message without ever invoking the
LLM. Exit code 0.

If you see ali's content in bob's response: the multi-tenant
invariant is broken. **Do not ship.**

### 3.3. QCM cross-tenant (bob tries to grade ali's QCM)

```bash
python -m app.cli submit-qcm --pseudo bob \
  --exercise-id <ali_exercise_id> --answers '[0,1,2]' --json
```

**Expected**:

```json
{
  "status": "error",
  "kind": "cross_tenant",
  "message": "Exercise <uuid> introuvable pour le pseudo 'bob'."
}
```

Exit code **5**. The error message is **identical** to the
"exercise not found" message — no leak of the foreign exercise's
existence.

### 3.4. Attempt_number isolation (two pseudos submit the same QCM)

The `attempt_number` counter is per `(pseudo, exercise_id)`. Bob
submitting to the same `exercise_id` as ali should start at 1, not
4 (ali's last).

```bash
# Generate a QCM for bob (need to upload a document for bob first)
python -m app.cli generate-qcm --pseudo bob --subject maths \
  --document-id <bob_doc_id> --n 3 --json
python -m app.cli submit-qcm --pseudo bob \
  --exercise-id <bob_exercise_id> --answers '[0,1,2]' --json
# → attempt_number: 1 (not 4)
```

## 4. Exit codes reference

| Exit | Meaning | Triggered by |
| --- | --- | --- |
| 0 | Success (or expected fallback: "no document", "manual review needed") | `upload`, `chat`, `generate-qcm`, `submit-qcm` happy path |
| 1 | Generic / unhandled error | Unexpected exception |
| 2 | Invalid file | `upload` with missing file, unsupported extension, or > 20 MB |
| 3 | OCR failure | `upload` with image where OCR service is down |
| 4 | Storage failure (ChromaDB / Postgres / S3 unreachable, or invalid QCM input) | `upload`, `chat`, `generate-qcm` storage init, `submit-qcm` with malformed answers |
| 5 | Invalid pseudo, document not found, or cross-tenant | All commands when the `pseudo` is malformed, the document/exercise doesn't exist for this pseudo, or cross-tenant access is attempted |

## 5. Inspecting the database

```bash
docker exec -it ktutor-postgres psql -U ktutor -d ktutor
```

```sql
\dt
-- documents, exercises, attempts

-- Documents indexed
SELECT student_pseudo, subject, filename, chunks_count, status
FROM documents;

-- QCMs generated
SELECT id, student_pseudo, type, jsonb_array_length(questions) AS num_q
FROM exercises;

-- Attempts submitted (per (pseudo, exercise_id))
SELECT student_pseudo, exercise_id, attempt_number, is_success, raw_answers
FROM attempts
ORDER BY submitted_at DESC
LIMIT 10;
```

## 6. Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `connection refused: localhost:8333` (S3) | SeaweedFS container not running | `docker compose up -d seaweedfs` |
| `connection refused: localhost:5432` (DB) | Postgres not running or wrong URL | Check `DATABASE_URL` uses `postgresql+psycopg://` |
| `No module named 'psycopg2'` | URL missing the `+psycopg` dialect | Use `postgresql+psycopg://` in `DATABASE_URL` |
| `LLM API key missing` | `LLM_API_KEY` not set or empty | Set in `backend/.env` |
| `InvalidPseudoError` | Pseudo doesn't match `^[a-zA-Z0-9_]{3,32}$` | Use 3-32 chars, alphanumeric + underscore only |
| `document_not_found` on a document you just uploaded | The upload may have failed silently | Check `SELECT * FROM documents;` |
| `UnicodeEncodeError: 'charmap' codec` on Windows console | cp1252 console vs UTF-8 rich output | Already fixed in commit `bfb6592` (Quick Fix). Update your local main. |
| FastEmbed model download fails on Windows | HuggingFace symlink warning | Set `HF_HUB_DISABLE_SYMLINKS_WARNING=1` or run as admin. The download still works. |

## 7. What is NOT covered by Phase 1

These arrive in later phases and are **expected** to fail or
return 404 / "not found" in Phase 1:

- No HTTP API (use the CLI). The FastAPI endpoints arrive in s09-s11.
- No web UI. The frontend arrives in s11.
- No JWT auth. The CLI takes `--pseudo` directly. Real auth in s12-s15.
- No streaming. The CLI returns one-shot. SSE arrives in s09.
- No progressive correction. s04 is all-or-nothing. Indices/hints arrive in s08.
- No copy-of-exam evaluation. OCR manuscrit + score extraction arrive in s18-s18b.
- No i18n (s21), accessibility audit (s22), observability (s23), alerting (s24), in-app
  notifications (s25), user documentation (s26). All Phase 5.

The Phase 1 POC is intentionally minimal: it validates the
architecture (multi-tenant RAG, deterministic QCM grading) and
provides a runnable skeleton that Phase 2 will build on.
